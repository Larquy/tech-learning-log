## 一、十进制数在底层怎么转换

### 1. 字符串（源码里的十进制数）→ 二进制

**本质**：源码里写的 `123` 是 **ASCII 码字符串**（`'1' '2' '3'`），**编译时才转成二进制** ✓

**算法（循环）**：从高位到低位逐个字符处理
```
累加器 = 0
对每个字符 c：
    屏蔽高位：c & 0FH      ; 去掉 ASCII 的 30H 前缀，得到数字本身
    累加器 = 累加器 × 10 + 该数字
```
👉 这就是"**算出来**"的过程：先屏蔽 ASCII 高位（等价于 `SUB 30H`），再乘 10 累加 ✓

### 2. 二进制 → 十进制（要显示时）

- **补码**：先**还原真值**（负数**取反加一**得到绝对值），再处理
- **无符号数**：直接处理
- **算法**：**反复除以 10 取余数，按逆序排列**得到十进制各位 ✓
- ⚠️ 这个过程**耗时**：数值越大，除 10 的循环次数越多 ✓（这正说明"二进制→十进制"比"十进制→二进制"贵 ✓）

## 二、BCD 码是什么

| 类型 | 每个字节存几位十进制 | 格式 |
|---|---|---|
| **非组合（非压缩）BCD** | **1 位** | **低 4 位有效，高 4 位为 0 或无关位** |
| **组合（压缩）BCD** | **2 位** | 高 4 位一位、低 4 位一位（**空间更紧凑**）|

- 编码规则：**用 4 位连续二进制位表示一位十进制数（0–9）**，超出 9 的取值要自己保证不出现 ✓
- **ASCII ↔ 非组合 BCD**：`'5'` = **35H**，`35H & 0FH = 05H` ✓（所以键盘输入要先用 `SUB 30H` / `AND 0FH` 变数字 ✓）

## 三、非组合 BCD 加法调整：**AAA**

### AAA 的三种情况

| 情况 | 触发条件 | 动作 |
|---|---|---|
| **① 无需调整** | AL 低 4 位在 **0–9** 且 **AF=0** | 直接接受结果（并把 AL 高 4 位清 0）|
| **② 结果超 9** | AL 低 4 位 **> 9** | **AL 加 6**、**AH 加 1**、**AF 置 1**、**清 AL 高 4 位** |
| **③ 十六进制进位** | **AF=1**（十进制没进位，但十六进制进了）| **AL 加 6** 补偿多进的 6 ✓ |

### AAA 使用前提（三条都要满足）

1. **必须先执行 `ADD` 或 `ADC`**（完成二进制加法）
2. **两个操作数必须是合法的非组合 BCD 码**
3. **加法结果必须在 `AL` 中**

### 多位 BCD 加法怎么实现

- 存储：**低位在低地址、高位在高地址**（倒序/小端排法）✓
- 循环：**从个位开始**，用 **`ADC`** 带进位加法，每轮结束 **SI/DI 向高位方向移动** ✓
- ⚠️ **AAA 调整后 AF 反映十进制进位，中间别用 `OR` 之类的指令破坏 AF 标志** ✓
- 循环结束：**检查 CF，若为 1 就把结果缓冲区最高位置 1**（多出来的那一位 ✓）


## 四、非组合 BCD 减法调整：**AAS**

### AAS 的三种情况

| 情况 | 场景 | 动作 |
|---|---|---|
| **① 无需调整** | 大数减小数，结果 0–9 且 **AF=0** | 直接接受 |
| **② 结果超 9** | 小数减大数产生**十六进制借位**、结果 >9 且 **AF=1** | **AL 减 6**，补偿多借的 6 ✓ |
| **③ 结果在 0–9 但 AF=1** | 例如 `1 − 9`：结果虽在 0–9，但 AF=1 表示**多借了 6** | **AL 减 6** 调整 ✓ |

### 老师讲的一个"简化视角"（值得记）

> 情况 **②** 和 **③** 的共同特征都是 **AF=1** —— 所以**理论上只要判断 AF 就够了** ✓
> 但 **Intel 芯片实际实现仍保留三种情况判断**，为的是**与加法（AAA）保持对称** ✓

### AAS 使用前提（与 AAA 对称）

1. 必须先执行 **`SUB` 或 `SBB`** 完成二进制减法 ✓
2. 操作数必须是合法的**非组合 BCD 码** ✓
3. 减法结果必须在 **`AL`** 中 ✓

### 多位 BCD 减法怎么实现（比加法多一步）

1. **先比较被减数与减数的大小** → 确定结果符号，必要时**交换操作数保证"大减小"** ✓
   - 比较**从高位到低位逐位进行**，发现不等立刻跳出 ✓
2. 用 **`SBB`** 带借位减法，**AAS 调整后 CF 反映十进制借位，供下一轮使用** ✓
3. 💡 **`DEC` 指令不影响 CF** —— 所以改地址指针时用 `DEC`，**不会干扰借位链** ✓

## 五、组合 BCD 调整：**DAA / DAS**（期末只要求"了解"）

- **`DAA`** 用于组合 BCD **加法**调整，**`DAS`** 用于**减法**调整 ✓
- 原理与非组合类型**类似**：分别对 **AL 低 4 位和高 4 位**做校正 ✓
- ⚠️ **标志位含义不同**（这是最容易被绕晕的地方）：

| 标志 | 非组合 BCD（AAA/AAS）| 组合 BCD（DAA/DAS）|
|---|---|---|
| **AF** | 十进制进位/借位（整体）| **低 4 位** BCD 是否产生十进制进位/借位 |
| **CF** | 十进制进位/借位（整体）| **高 4 位** BCD 是否产生十进制进位/借位 |

📌 **期末要求**：**非组合类型必须掌握，组合类型属于了解范畴** ✓

## 六、乘除法指令与溢出处理

### 无符号乘法 `MUL`（单操作数）

| 位数 | 被乘数 | 结果存放 |
|---|---|---|
| 8 位 × 8 位 | AL | **AX** |
| 16 位 × 16 位 | AX | **低 16 位在 AX、高 16 位在 DX** |

- ⚠️ **结果的高半部分非零 → CF 和 OF 置 1**（说明"结果装不下了"✓）

### 带符号乘法 `IMUL`

- 操作数按**补码**解释，其余行为与 `MUL` 相同 ✓

### 无符号除法 `DIV`

| 位数 | 隐含被除数 | 商 / 余数 |
|---|---|---|
| 8 位除数 | **AX** | 商 → **AL**，余数 → **AH** |
| 16 位除数 | **DX:AX 拼接的 32 位数** | 商 → **AX**，余数 → **DX** |

### 带符号除法 `IDIV`

- 操作数按**补码**解释，配合 **`CBW` / `CWD` 做符号扩展** ✓
- **`CBW`**：把 **AL 的符号位扩展到 AH** ✓
- **`CWD`**：把 **AX 的符号位扩展到 DX** ✓

### 除法异常处理

- **除数为零 或 商超出目标寄存器范围 → 触发 `INT 0` 中断** ✓
- Windows 会**拦截该中断并显示异常信息** ✓
- 👉 所以 `DIV` 之前一定要准备好 DX（`CWD` 或 `XOR DX,DX`）✓

## 七、BCD 码乘法

### `AAM` 指令

- 对 **AL 中的二进制乘积**做调整：**除以 10**，**十位存 AH、个位存 AL** ✓
- 影响的标志：**SF、ZF、PF** ✓；**OF、CF、AF 无定义** ✓

### 多位 BCD 乘法步骤

1. **被乘数每一位 × 乘数每一位 → 得到部分积** ✓
2. **每个部分积用 `AAM` 调整为两位 BCD 码** ✓
3. **部分积按位权错位相加**，**每次加法后要用 `AAA` 调整** ✓
4. 最终累加结果仍需加法调整 ✓
5. 📌 原则：**先乘调、再加调** ✓

## 九、这一章的易错点清单（背下来）

1. **`AAA`/`AAS` 必须紧跟 `ADD/ADC` 或 `SUB/SBB`**，且结果在 AL 中 ✓
2. **`AAA`/`AAS` 之后 AL 的高 4 位被清 0**（一定回到非组合格式 ✓）
3. **多位加减要从低位开始接力**（加法 `ADC`、减法 `SBB` ✓）
4. **`DEC` 不影响 CF** → 改指针时用它，不会破坏借位/进位链 ✓
5. **`DIV` 前沿务必准备好 DX**（否则商溢出 → INT 0 ✓）
6. **组合 BCD 的 AF/CF 含义与非组合不同**（AF 管低 4 位、CF 管高 4 位 ✓）
7. **`AAM` 会改 SF/ZF/PF**，但 **OF/CF/AF 无定义** ✓
