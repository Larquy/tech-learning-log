# 两道题：偶数奇数的排序可行性、翻转计算器模拟

2026-11-19　｜　数据结构与算法　刷题记录

## 一、糖果分装：偶数全给阿离，奇数全给阿信

题意：n 包糖果，偶数包归阿离、奇数包归阿信，可以任意排序，问能否让阿离在任意时刻都严格多于阿信。

结论：偶数之和大于奇数之和就 YES，否则 NO。

必要性好说，全部拿完后阿离手里就是偶数总和，阿信是奇数总和，最后时刻也要严格大于。

充分性靠构造：所有偶数排在前面，奇数排在后面。偶数阶段差值一路上涨，奇数阶段一路下降，降到最后一个奇数时最小，正好等于两边总和的差。它大于零，中间任何时刻都更大。

坑：一开始写成数包数，`if (x%2==0) cnt1++;`，比的是有多少包而非多少颗糖。三组样例里两组恰好能蒙对，只有 1 2 3 4 那组会露馅（按包数 2 比 2 判 NO，实际应是 YES）。

教训：这种计数题先拿最简单的样例手算一遍再写循环。

## 二、翻转计算器

题意：读入若干操作行，形如运算符加整数，最后一行为 #。支持加减乘整除，非法运算符输出 invalid input、除零输出 divided by zero，两者都不改变当前结果。每完成两次正常计算，第三次正常计算的结果要被翻转（数字倒序，保留符号，去前导零），且翻转后存回结果。

输入没有给操作个数，`while (cin >> op)` 一直读到 # 就 break。读到 # 之后别再读整数，那一行只有字符。

非法运算符也要照常读掉后面的整数，不然缓冲区错位，下一行会把数字当运算符读。

switch 分流，除零放在 case '/' 里面单独判，default 接非法字符。错误分支只打印提示，不动结果。

翻转用算术实现，不转字符串：

```cpp
int rev(int x) {
    int s = 1;
    if (x < 0) { s = -1; x = -x; }
    int y = 0;
    while (x > 0) { y = y * 10 + x % 10; x /= 10; }
    return s * y;
}
```

先取绝对值，循环取末位拼新数，最后补符号。拼的过程自动丢掉前导零，30 翻过来是 3，100 翻过来是 1。

计数只数正常计算：出错的两行既不计数也不清零，计数器原地不动。样例二正好卡在这条上，`+5` 计 1、`%99999` 不动、`+3` 计 2、`/0` 不动、`+4` 得 12 触发翻转输出 21。

一个自己的教训：给学生讲这道题时，我在纸上推演把 8+4 记成了 21，于是断言“出错必须清零”，跟他 AC 的代码对不上。回头重算才发现是 8+4=12，翻转成 21，正好是样例。

手推模拟题要把每一步的中间值写在纸上，别在脑子里跳步。跳一步就会得出相反的结论，还会理直气壮地说别人错了。
