# 输入输出优化与几个数值陷阱

日期：2026-11-01　课程：数据结构与算法

> 一道 $n\le 10^6$ 的判断题超时后复盘：算法是 $O(n)$ 却 TLE，问题全在 I/O 和数值处理上。这篇记两行加速的原理、`endl` 的代价、整数除法的截断，以及用乘法代替除法时要注意的溢出。

## 一、TLE 不等于算法慢

看到超时，先分清两类原因：

算法复杂度超标（比如该用 $O(n\log n)$ 写成了 $O(n^2)$）；
常数太大（I/O 慢、频繁刷新缓冲区、用了低效容器）。

$n=10^6$ 时，200 万次输入加 100 万次输出，光 I/O 就能吃掉一两秒。同样的算法，加不加那两行，差距可能有三到五倍。

## 二、两行加速

```cpp
ios::sync_with_stdio(false);
cin.tie(0);
```

**第一行解除与 C 标准库的同步**。默认 `cin`/`cout` 与 `scanf`/`printf` 共用缓冲区，每次读入都要对齐一次，保证混用不乱序。关掉之后各用各的缓冲区，快很多。

代价是不能混用两套 I/O，否则输出顺序不确定。

**第二行解除输入输出绑定**。默认每次 `cin >>` 之前都会把 `cout` 冲刷一次，为了交互式程序能先看到提示再等待输入。解绑后不再自动冲刷。`cin.tie(0)` 与 `cin.tie(nullptr)` 等价。

**把 `endl` 换成 `'\n'`**。`endl` 除了换行还会强制刷新缓冲区，每次刷新是一次系统调用。十万次以上就该换掉，一百万次差异非常明显。

## 三、整数除法会截断

```cpp
int v, s;
float res = v / s;    // 错
```

`v / s` 先按整数算完再转 `float`，7/2 得到 3，小数位在赋值前就没了。

正确写法是把一边转成浮点：

```cpp
double res = (double)v / s;
```

## 四、能整除就别用浮点

判断 $\frac{v}{s} > w$ 等价于 $v > w\cdot s$（$s>0$），直接用整数比较，没有精度问题，也不用担心 `float` 只有 7 位有效数字。

但要注意溢出：$v,w,s$ 最大 $10^6+1$，$w\cdot s$ 可达 $10^{12}$ 量级，`int` 上限约 $2.1\times 10^9$，装不下，必须 `long long`。

一句话：**比较比值用乘法，乘法前看范围**。

## 五、边界与题面

等号归哪一支要看题面用词：超过、高于是不含等号；不低于、不小于是含等号。样例里通常埋了一组恰好相等的数据，跑一遍就知道。

输出的大小写照抄题面。有的题写 `Yes`/`No`，有的写 `Yes`/`NO`，一个字母不同就是 WA。

## 六、检查清单

先看约束：$n$ 到 $10^6$ 就先加上两行加速、把 `endl` 换 `\n`。

再看类型：两个 `int` 相除、乘积是否超过 $2\times 10^9$、`long long` 是否需要。

最后看边界：等号、等于 0、等于 1、最大最小值，各造一组数据试。

## 七、自测

1. 为什么关掉同步之后不能混用 `cin` 和 `printf`？（答：两套缓冲区独立，顺序不确定）
2. `v/s` 里 `v`、`s` 都是 `int`，想得到小数要改哪里？（答：把 `v` 转 `double`，或直接把变量定义成浮点）
3. 判断 $v/s > w$ 为什么推荐用 $v > w\cdot s$？需要注意什么？（答：避免浮点误差；注意乘法溢出，用 `long long`）
4. `endl` 比 `'\n'` 慢在哪？（答：强制刷新缓冲区，每次一次系统调用）
