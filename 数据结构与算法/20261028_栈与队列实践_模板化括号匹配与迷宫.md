# 栈与队列实践：模板化、括号匹配与迷宫回溯

日期：2026-10-28　课程：数据结构与算法

> 这一轮把链栈、链队列改成了类模板，又用它们做了括号匹配和迷宫求解。记录三件事：模板怎么落地、输入循环为什么别用 peek、回溯算法怎么用栈实现。

## 一、链式结构模板化

**三步改造**

结点先变成模板：`template <class T> struct Node { T data; Node<T>* next; };`

类声明加模板头，类内的指针类型跟着改：`Node<T>* top`、`Node<T>* front`。

成员函数的实现必须留在头文件里，每条前面加 `template <class T>`，函数名前加 `LinkStack<T>::`。原因：模板不是实体代码，编译器在实例化时才生成，分成 .cpp 会找不到定义。

**代价**

报错信息变得又长又难读，一个类型错误能刷出几十行。定位方法是从最后一条错误往前看，最后一条往往指到真正的问题。

## 二、输入循环：别用 peek 判行尾

原来的写法：

```cpp
while (cin >> x) { ...; if (cin.peek() == '\n') break; }
```

在 Windows 上失效。换行实际是 `\r\n`，`peek` 拿到的第一个字节是 `'\r'`，跟 `'\n'` 不等，判断永远不成立。表现是第一个输入循环把后面几行的数据全吃掉，第二个循环拿不到任何数据——看起来像“队列坏了”，其实是输入没分段。

**可靠写法**：读整行再逐个解析。

```cpp
string line;
getline(cin, line);
istringstream iss(line);
while (iss >> x) { 入栈/入队; }
```

`getline` 负责处理换行，`istringstream` 负责拆分，两者都不依赖平台换行约定。

左括号入栈；右括号先 `GetTop` 判栈空（空则该右括号多余），再判类型是否配对（不配对则该位置出错），都通过才 `Pop`。扫完栈非空说明左括号多余。

两个细节：用 `GetTop` 而不是 `Pop`，因为报错时要说明栈顶是什么符号，弹掉就说不清了；配对判断写成独立函数 `bool match(char l, char r)`，三个条件并列，主循环保持干净。

## 四、迷宫回溯

**方向数组**：`dx[4]={0,1,0,-1}`、`dy[4]={1,0,-1,0}` 对应右下左上。四方向循环代替四段重复代码，改搜索顺序只动数组。

**栈里存坐标**：定义 `struct Pos{int x,y;}`，用 `LinkStack<Pos>`，模板在这里省了一次重写。

**主循环三步**：取栈顶；试四个方向，遇到 0 就标记成 2、压栈、跳出方向循环；四方向都不通则弹栈回溯。

**必须标记**：走过的格子改成 2，否则相邻两个空格会互相压栈，原地打转直到栈溢出。标记同时保证了每个格子最多入栈一次，循环必然终止。

**输出顺序**：栈里是终点在上、起点在下，要全部弹到一个数组再倒序打印，才是起点到终点的顺序。

## 五、易错点

- 模板的成员函数写进 .cpp，链接时报 undefined reference
- `for (int i=0; s[i]=='\0'; i++)`：条件写反，循环一次都不进
- 用 `s[i]` 判栈里剩几个：计数该看 `Empty()`，与字符串下标无关
- 迷宫起点终点放在墙格上（(0,0)、(7,7) 是墙）
- 方向循环里忘了 `break`，一个位置分叉压入多个邻居
- 回溯时用 `Pop` 取当前点，位置当场丢失
