# 最短路径：Dijkstra 与 Floyd

2026-11-19　｜　数据结构与算法　第七章 图

两个算法解决同一类问题的两种需求。Dijkstra 从一个起点算到其余各点，Floyd 一次算完所有点对。都是第七章，课上连着讲。

## 一、Dijkstra：贪心加松弛

维护 `dist[]` 记起点到各点目前已知的最短距离，起点自己 0，其余设无穷。

每一轮做三件事：从没确定的点里挑 `dist` 最小的，标记为确定；用它更新邻居，若 `dist[u] + g[u][v] < dist[v]` 就改小；重复 n 轮。

## 二、跟 Prim 差在哪

Prim 的数组记的是"这个点到已连通那一坨的最近距离"，更新时看边权。Dijkstra 记的是"从起点一路走过来的累计距离"，更新时算 `dist[u] + w`。

一个是往内看，一个是从起点往外算。两者的循环骨架几乎一样，改两行的事，但问题不同。

## 三、算例

图上五条边：0-1 权 2、0-2 权 3、1-2 权 1、1-3 权 4、2-3 权 5。从 0 出发。

初始 `dist = [0, 2, 3, ∞]`。

挑 1（2）确定，更新：到 2 是 3，到 3 是 6。

挑 2（3）确定，更新 3：3+5=8 大于 6，不改。

挑 3（6）确定。

结果 `[0, 2, 3, 6]`。

## 四、前提

边权不能为负。Dijkstra 一旦确定就不再回头改，负权会出现"后来发现更近"的情况。有负权要用 Bellman-Ford。

## 五、Floyd：一轮放开一个中转点

`dist` 是距离矩阵，`path` 记这条最短路经过哪个中转点，-1 表示直达。

初始就是邻接矩阵。上标表示"允许经过哪些点中转"，第 k 轮放开第 k 个点。

课上那张幻灯片是三个点的图：0→1 是 4，0→2 是 11，1→0 是 6，1→2 是 2，2→0 是 1，2→1 没有边。

放开 0：只有 2→1 变了，原来无穷，走 2→0→1 得 1+4=5，`path[2][1]` 记成 0。

放开 0 和 1：0→2 从 11 变成 4+2=6，`path[0][2]` 记成 1。

放开全部：1→0 从 6 变成 2+1=3，`path[1][0]` 记成 2。

三轮过后，任何点对绕几道弯的情况都试过了。

## 六、代码只有三层循环

```
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (dist[i][k] + dist[k][j] < dist[i][j]) {
                dist[i][j] = dist[i][k] + dist[k][j];
                path[i][j] = k;
            }
```

## 七、三个坑

k 必须在最外层。放里面就错了，因为第 k 轮要基于上一轮的完整结果。

没有边的两点填 99999 之类的数，别用真正的无穷。两个 99999 相加会溢出成负数，判断就反过来。

`dist[i][i]` 初始化成 0，不然后面算出来的最短路径里会带上自己。
