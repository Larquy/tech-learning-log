# 多维数组寻址与特殊矩阵压缩存储 · 稀疏矩阵转置

日期：2026-10-08　课程：数据结构与算法

> 课堂纪要整理版。主线：**数组怎么算地址 → 特殊矩阵怎么压 → 稀疏矩阵怎么存与转置 → 课程进度**。

## 一、多维数组的寻址规则

### 1. 遍历/下标变化的顺序：**从右向左** ⭐

- 多维数组遍历时：**先循环最右侧的下标 K，再循环 J，最后才循环最左侧的 I** ✓
- **考研常考二维矩阵形式**，三阶情况同理适用该规则 ✓（记住"最右的下标动得最快"这一条）

### 2. 顺序存储支持随机访问

- 只要知道**起始地址**和**元素大小 $L$**，就能直接算出任意元素的物理地址 ✓
- ⚠️ 地址计算时**必须把"元素所占字节数 $L$"乘进去**，$L$ 按题目给定（固定字节数）✓

### 3. 行优先存储的下标计算

- **行优先**：**行下标在前、列下标在后** ✓（C 语言下标从 0 开始）
- 推广到一般维度的公式较复杂 → **核心记忆点就是"从右向左的优先顺序"这条规则** ✓
- Z 字形等非常规形状属于**数学推导问题**；计算机的"基本问题"聚焦**行优先 / 列优先**寻址 ✓

## 二、特殊矩阵的压缩存储

### 0. 压缩存储的核心原则

- 特殊矩阵与稀疏矩阵都要**满足优先顺序约束**，不能随意乱存 ✓
- 自己封装 `class` 时可以自定义优先方式（如对角优先），但**默认通常行优先** ✓
- 📌 本章重点是**数学逻辑关系与物理存储的对应**，程序实现难度**低于**后面的十字链表 ✓

### 1. 对称矩阵

- 满足 $A_{ij}=A_{ji}$ → **只需存上三角或下三角 + 对角线** ✓
- 存储元素个数：$\dfrac{N(N+1)}{2}$ ⚠️ **不是 $\dfrac{N^2}{2}$** ✓（这条最爱考）
- 按行优先存下三角时，一维下标 $K$ 从 $0$ 到 $\dfrac{N(N+1)}{2}-1$ ✓
- **要掌握的就是 $I,J,K$ 的对应公式** ✓

### 2. 三角矩阵（与对称矩阵的差异）

- 除三角区域外，**还要额外存一个常数项 $C$（或零元素）** ✓
- **两种存法都要理解**：

| 存法 | 影响 |
|---|---|
| 教材：$C$ 存在 **$S_0$（首位）** | 后面元素的对应关系 = 对称矩阵的公式 **再 +1** ✓ |
| PPT/部分教材：$C$ 存在**末尾** | 前面部分与对称矩阵**完全一致，不用 +1** ✓ |

👉 **考试以教材为准**；核心是**记住对应关系**，而不是死背公式 ✓

### 3. 对角矩阵（本科以三对角为主）

- 非零元素集中在主对角线附近的**带状区域** ✓
- **三对角矩阵元素总数 = $3N-2$** ✓（第一行、最后一行各 2 个，中间各行 3 个 ✓）
- 行优先存储的一维下标：$K=2(I-1)+J-1$ ✓（$I,J$ 从 1 开始、$K$ 从 0 开始）
  - 比"对角优先"的公式**更好推导**，推荐用这一版 ✓
- 五对角及以上计算量大、考试极少涉及 → **掌握三对角推导方法即可** ✓


## 三、稀疏矩阵的存储

### 1. "稀疏"的两种定义（工程 vs 数学）

| 角度 | 判定 |
|---|---|
| **工程** | 非零元占比**远小于 5%** 就视为稀疏矩阵 ✓ |
| **数学** | 非零元数量的**量级仍是 $M\times N$** → 算法复杂度分析中**常数因子不影响量级判定** ✓ |

💡 但**实际运算次数会受常数影响** —— 所以"算法复杂度"与"实际执行次数"要分开看 ✓

### 2. 三元组顺序表

- 每个非零元用 **（行号，列号，值）** 唯一确定 ✓
- ⚠️ **顺序表首位必须先存"矩阵行数、列数、非零元个数"** —— 否则无法还原矩阵形状 ✓
- ⚠️ 三元组**必须按行优先顺序排列** —— 这是后续**转置算法的前提条件** ✓

### 3. 链式存储：十字链表

- 稀疏矩阵的链式存储采用 **十字链表** —— **本章最复杂、应用最广的结构** ✓
- 广义表的"引用计数"存储法**只在广义表里用** ✓
- **十字链表的思想在后面章节会反复出现**，值得多花时间 ✓

## 四、三元组顺序表的转置

### 1. 简单转置（对照用，效率差）

思路：**以目标矩阵为目标**，按列号从小到大依次填充
```
外层：循环列号 col
内层：遍历源三元组，找列号 == col 的元素
      交换行列后，放入目标三元组的下一个位置
```
- 时间复杂度 **$O(M\times N^2)$** ⚠️ —— 比常规二维数组转置的 $O(M\times N)$ **还差** ✗
- 教训：**压缩存储省了空间，却可能让时间变贵** ✓

### 2. 快速转置（一次遍历定位）

思路：**直接遍历源三元组，把每个元素一次性放到目标的正确位置** ✓

需要**预先计算两个辅助向量**：
1. **每列的非零元个数** $num[\,]$（用来算"这一列要占几个位置"）✓
2. **每列第一个非零元在目标数组中的位置** $cpot[\,]$ ✓
   - 第一列的首个非零元位置初始为 0（或 1，按下标约定 ✓），后续列由**前几列累计**得到 ✓

- 预计算完成后，转置过程**只需单次遍历** ✓
- 时间复杂度降到 **$O(M\times N)$**，**同时保持压缩存储的空间优势** ✓（这才是标准答案）

## 六、本篇要点清单

1. 下标变化顺序：**从右向左**（最右侧下标动得最快）✓
2. 地址计算 = 首地址 + **下标偏移 × 元素字节数 $L$** ✓
3. 对称矩阵存储个数 = $\dfrac{N(N+1)}{2}$（**不是 $\dfrac{N^2}{2}$**）✓
4. 三角矩阵多存一个常数项 $C$：**教材放首位 → 下标 +1；放末尾 → 不 +1** ✓（以教材为准）
5. 三对角矩阵元素总数 = $3N-2$；行优先 $K=2(I-1)+J-1$ ✓
6. 三元组顺序表：**首位存行列数与非零元个数**、**必须按行优先排** ✓
7. 转置：简单法 $O(M\times N^2)$ ✗ → **快速转置（两个辅助向量）$O(M\times N)$** ✓
8. 十字链表 = 本章最复杂也最常用，后面章节反复出现 ✓
