# 里氏替换原则与合成复用原则

日期：2026-10-19　课程：设计模式与重构

> 本篇整理两个最常被误解的原则：里氏替换（继承的边界在哪）和合成复用（什么时候别用继承）。文末附七大原则总表和自测。23 种模式的分类与创建型模式另见 [20261019_23种模式的分类与创建型模式](20261019_23种模式的分类与创建型模式.md)。

## 一、里氏替换原则（LSP）

### 定义

设有类型 T1 的对象 O1，类型 T2 的对象 O2。如果在程序里把 O1 换成 O2，程序的行为**保持不变**，那么 T2 就是 T1 的子类型。

注意这句话的重心：不是"能编译通过"，而是"行为不变"。编译通过但是跑出来结果不一样，就不符合 LSP。

允许子类做的事只有一件：**优化算法效率**。输入输出的契约不能动。

### 重写和重载，风险完全不同

**重写（Override）**是子类改父类已有方法的行为。这个动作风险高，因为你把父类对象交给别人之后，别人可能塞进来一个子类对象，而那个子类的重写版本和你预期的不一样，行为就不可控了。

**重载（Overload）**只是加了一个同名函数，参数列表或返回类型不同，原有调用完全不受影响，安全性高。

一句话记：重写改的是"已有调用会走到哪"，重载只是"多了一个入口"。

### 契约约束

父类已经实现了的方法，等于对外公布了规约。子类覆盖非抽象方法，就是在改这份规约，继承体系就被破坏了。

所以子类该做的两件事是：**扩展新方法**、**实现抽象方法**。不该做的是覆盖父类的非抽象方法。

### 输入输出兼容性

这条是 LSP 落到代码上的具体判据：

**前置条件要放松，不能收紧**。父类方法接受 $[0, 100]$ 的入参，子类就不能收窄成 $[0, 50]$，因为调用方手里可能真有个 80，换进来就崩了。

**返回值要收紧，不能放松**。父类返回 `Number`，子类返回 `Integer` 是合法的（协变返回），反过来不行，因为调用方可能已经按 `Integer` 处理了。

### Map 与 HashMap 的例子

方法签名 `void f(Map<K,V> m)` 改成 `void f(HashMap<K,V> m)`，看起来只是更具体了，实际上把入参范围收窄了。原来传一个 `TreeMap` 能跑的代码，现在编不过或者得改。这就是违反"前置条件不能收紧"的典型。

反过来，如果 `f` 原来就要 `HashMap`，改成要 `Map` 是安全的，因为放宽了。

## 二、合成复用原则（优先组合，少用继承）

### 组合与聚合

**组合**：不可分割的整体，缺了部分整体就失效。车身和发动机。

**聚合**：可分离的关联，个体的增减不影响整体存在。班级里的学生，走一个人班还在。

落到 UML 上，组合画实心菱形，聚合画空心菱形。落到代码上，组合通常是整体自己 `new` 出来的，聚合一般是外部注入。

### 继承的毛病

- 破坏封装。子类能看见父类的实现细节，父类一改，子类跟着崩
- 耦合度高。父类改动会波及所有子类
- 复用不灵活。继承是编译期定死的，运行时换不了
- 侵入性强。为了复用一段逻辑，硬把两个不相关的类塞进继承关系里

组合的做法是把已有对象当成员变量放进来，新对象调它的方法。要换实现，换个成员对象就行，运行期也能换。

### 汽车加颜色的类爆炸

如果按继承做：油车、电车两种动力，白、黑、红三种颜色。

继承树会变成白色油车、黑色油车、红色油车、白色电车……共 $2\times3=6$ 个类。再加一种动力，类数涨到 $3\times3=9$。

用组合做：汽车基类下面只分油车、电车两个子类，颜色做成独立的类，作为成员变量组合进去。新增一种颜色只加一个类，新增一种动力只加一个子类。

维度一多，继承就是乘法，组合是加法。这是合成复用原则最直观的理由。

### 银联卡与发卡行的设计

课堂练习：给银联设计一个是组合关系的管理类图，要同时体现卡类型（储蓄卡、信用卡）和发卡行（建行、工行等）。

关键判断是：

- **卡类型用继承**，储蓄卡和信用卡继承同一个卡基类，因为它们是"是一种"的关系
- **发卡行用聚合**，银行对象在卡外面独立存在，卡只是引用它，删掉卡银行还在

如果两个维度都用继承，类数就是乘法，$2\times N$ 个；用继承加聚合，是 $2+N$ 个。这条正好印证上一节的结论。

### 组合之后谁是业务主体

组合出来的对象落在**具体组合结果**上：白色油车、黑色电动车。颜色和动力类型这些参与组合的类只是配件，不是独立的业务主体。

这条在建模时很实用：画类图时，"白色油车"才是实体，颜色不该单独当一个业务对象去管理生命周期。

## 三、七大设计原则回顾

| 原则 | 一句话 | 典型手段 |
|---|---|---|
| 开闭原则 | 对扩展开放，对修改关闭 | 继承、组合、多态 |
| 依赖倒置 | 高层和低层都依赖抽象 | 接口、依赖注入 |
| 单一职责 | 一个类只干一件事 | 拆类、拆方法 |
| 接口隔离 | 接口按功能分门别类 | 拆接口，不强迫实现无关方法 |
| 迪米特法则 | 少跟陌生人打交道 | 减少链式调用、加中间层 |
| 里氏替换 | 子类替换父类，行为不变 | 前置放松、返回收紧、不覆盖非抽象方法 |
| 合成复用 | 优先组合聚合，少用继承 | 成员变量 + 委托 |

七条里，开闭是总目标，其余六条都是达成它的手段。里氏替换管"继承用得对不对"，合成复用管"该不该用继承"，两条正好是一对。

## 四、易错点

- 里氏替换说的"行为不变"是**语义上**的不变，编译通过不等于满足
- 重写有风险、重载没风险，这两个词常被写反
- 前置条件放松是子类该做的方向，写紧就违反 LSP，很多人记反
- 返回值放宽也不行，只能收紧（协变返回）
- 组合和聚合的区分标准是"部分能不能独立存活"，不是"有没有用指针"
- 组合画实心菱形、聚合画空心菱形，别画反
- 多维度扩展时先算一下类数，$2\times3$ 和 $2+3$ 的差距一看就明白该用哪个
