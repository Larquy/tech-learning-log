# 设计模式阶段小结：原则、分类与创建型三兄弟

日期：2026-10-26　课程：设计模式与重构

> 把这一阶段学的串成一条线：七大原则是判断标准，23 种模式是手段，创建型里的三个工厂是重点。细节散在 20261019 与 20261026 几篇里，这篇只留主干和对照。

## 一、七大原则，先记住谁是目标

| 原则 | 一句话 | 解决什么 |
|---|---|---|
| 开闭原则 | 对扩展开放，对修改关闭 | 这是目标，其余六条是手段 |
| 单一职责 | 一个类只干一件事 | 职责混杂，改一处崩一片 |
| 里氏替换 | 子类替换父类后行为不变 | 继承滥用，逻辑被悄悄改坏 |
| 依赖倒置 | 高层和低层都依赖抽象 | 上层被下层实现绑死 |
| 接口隔离 | 接口按功能拆分，不强塞 | 客户端被迫实现用不到的方法 |
| 迪米特法则 | 少和陌生人打交道 | 对象之间耦合过密 |
| 合成复用 | 优先组合而非继承 | 继承导致类爆炸与封装破坏 |

一句话记忆：开闭是终点，其余六条是通往终点的路。

## 二、23 种模式的三类划分

创建型 5 种，管对象怎么产生：简单工厂（不算 GoF 正式成员）、工厂方法、抽象工厂、单例、建造者、原型。

结构型 7 种，管类与对象怎么拼成更大的结构：适配器、桥接、组合、装饰、外观、享元、代理。

行为型 11 种，管对象之间怎么通信与分派职责：责任链、命令、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者、解释器。

## 三、三个工厂的区别

| | 简单工厂 | 工厂方法 | 抽象工厂 |
|---|---|---|---|
| 工厂形态 | 一个具体类加 switch | 抽象工厂加多个具体工厂 | 抽象工厂加一族产品 |
| 新增产品 | 要改 switch，违反开闭 | 加一个工厂类即可 | 产品族内加法即可，加新族要改接口 |
| 产品数量 | 单一产品 | 单一产品 | 一族相关产品 |
| 典型场景 | 构造复杂、种类少 | 需要扩展、客户只知工厂名 | 多产品族要保持一致 |

三者是一条演进线：简单工厂最省事但违反开闭，工厂方法把工厂也抽象掉换来扩展性，抽象工厂再进一步解决一族产品的一致性问题。
## 四、创建型另外三个

单例：保证一个类只有一个实例，提供全局访问点。关键不是怎么 new，而是怎么防止别人 new——构造函数私有、静态方法返回唯一实例。懒汉式要处理线程安全，饿汉式简单但类加载即创建。

建造者：把复杂对象的构造过程拆成一步步，最后统一 build。适合参数多、可选参数多、构造顺序有讲究的对象。和工厂的区别是，工厂关心“造出哪个产品”，建造者关心“怎么一步步造出这一个”。

原型：通过复制已有对象来创建新对象，不走构造函数。适合创建成本高、或者需要保留某个状态的场景。深拷贝与浅拷贝是考点。

## 五、UML 六种关系速查

| 关系 | 画法 | 代码表现 |
|---|---|---|
| 继承 | 实线加空心三角 | extends 类 |
| 实现 | 虚线加空心三角 | implements 接口 |
| 关联 | 实线，可带箭头 | 成员变量，长期持有 |
| 聚合 | 实线加空心菱形 | 成员变量，外部传入 |
| 组合 | 实线加实心菱形 | 成员变量，内部 new |
| 依赖 | 虚线加开放箭头 | 参数、局部变量、返回值 |

三角是“是”，菱形是“有”，箭头是“用”；实心强于空心，实线强于虚线。菱形永远贴着整体那一端。

## 六、六个易混点

一、把 23 种模式当成 23 个要背的名字。真正要记的是“什么变化点对应哪个模式”，名称只是标签。

二、简单工厂不算 GoF 的 23 种，很多教材单独列，考试写“工厂方法模式的一种简化形式”比较稳妥。

三、抽象工厂和工厂方法最容易混。判据是有没有“产品族”概念：一次只造一种产品是工厂方法，一次造一族配套产品才是抽象工厂。

四、聚合和组合在图上只差实心空心，代码上差在部分对象的来源，别只看图不看代码。

五、依赖倒置不是“依赖接口就不算依赖”，它的关键是高层不编译依赖低层的具体类。

六、开闭原则最容易被滥用成“什么都要能扩展”，实际工程里要先判断变化点是否真的会变，为假想的变化写抽象是过度设计。

## 七、自测

一、给一个 switch 判断类型的代码片段，问该用哪个工厂模式改造，为什么。

二、某系统要生产 Windows 与 Mac 两套风格的按钮和滚动条，用工厂方法还是抽象工厂，说明理由。

三、画出 SLF4J 那两张图里 Logger 与 LocationAwareLogger 的关系，标出箭头样式。

四、单例的懒汉式为什么需要双重检查，不加会出什么问题。

五、判断：只要用了接口，就符合依赖倒置原则。为什么。
