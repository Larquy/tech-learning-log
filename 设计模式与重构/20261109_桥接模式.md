# 桥接模式

日期：2026-11-09　课程：设计模式

> 一句话：把两个各自会变化的维度拆开，用组合代替继承，让类数量从乘积变成加法。

## 一、它解决的问题

画形状和颜色，如果全用继承：红圆、蓝圆、红方、蓝方。

两个维度各两个取值，就要四个类。三个颜色四种形状，十二个类。加一个颜色，所有形状都要再写一份。

这就是类爆炸，根因是把两个独立的维度塞进了同一条继承链。

## 二、结构

两个角色：抽象部分和实现部分。

抽象部分：Shape 及其子类，回答“是什么”，内部持有一个 Color 指针。
实现部分：Color 及其子类，回答“怎么做”，单独成一条继承链。

两边各自扩展，接口在抽象层握手。

```cpp
class Color {
public:
    virtual ~Color() {}
    virtual const char* name() const = 0;
};

class Red : public Color {
public:
    const char* name() const { return "红"; }
};

class Shape {
protected:
    Color* color;                  // 桥
public:
    Shape(Color* c) : color(c) {}
    virtual ~Shape() {}
    virtual void draw() const = 0;
};

class Circle : public Shape {
public:
    Circle(Color* c) : Shape(c) {}
    void draw() const { std::cout << color->name() << "圆\n"; }
};
```

调用：`Circle c(new Red()); c.draw();`

加颜色只加 Color 子类，加形状只加 Shape 子类，互不影响。

## 三、和策略模式的区别

代码形状几乎一样，都是一个类持有另一个抽象类的指针。区别在意图。

策略：换算法。同一个对象在不同时刻换不同策略，调用方知道有策略存在。

桥接：两个维度独立演化。结构上分离，为了以后两边各自加东西。调用方通常不关心实现换了没有。

判断办法：如果这个被持有的对象会在运行时频繁替换，多半是策略；如果它一开始就定了、只是为了让两条继承链分开，多半是桥接。

## 四、什么时候该用

出现「A的B」这种组合类名，比如 红色圆形、Linux 按钮，说明两个维度被混在一起了。

一个类里既有业务逻辑又有平台细节，比如界面逻辑要同时跑 Windows 和 Linux。

更换实现不需要重新编译抽象部分，两边可以独立发布。

## 五、代价

多一层间接，一次虚函数跳转。

类的数量变成相加，但每个类更小、职责更单一。

如果只有一个维度会变，用继承就够了，别为了模式而模式。
