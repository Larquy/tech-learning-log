# Linux/WSL 与 Git 工作流

日期：2026-09-21　类别：工具与工程

## 结论先行

日常工作流：**在 WSL 里写代码 → git 提交 → 推到 GitHub**；提交前跑一次隐私扫描（本仓库装了 pre-commit 钩子）。

## WSL / Linux 常用

```bash
pwd ls cd ..                 # 位置
cp mv rm -r                  # 复制/移动/删除
grep -rn "关键字" .           # 递归搜索内容
find . -name "*.c"           # 按名字找文件
head -20 file / tail -f log  # 看头/追日志
chmod 600 file               # 改权限（私密文件用）
ps aux | grep python         # 看进程
```

## Git 最小工作流

```bash
git status                   # 现在有什么改动
git add -A                   # 全部加入暂存
git commit -m "主题"          # 提交（写清做了什么）
git push                     # 推到远端
git log --oneline -5         # 看最近提交
git remote -v                # 远端地址
```

**提交信息写法**：`科目 主题`，例如 `数据结构 链表反转`。
以后翻 log 就是一条学习时间线。

## 隐私保护（重要）

- 公开仓库**不放**：学号、成绩、排名、简历、联系方式、个人材料（docx/xlsx/pdf/图片）
- 本仓库装了 **pre-commit 钩子**：提交前自动扫描上述内容，命中就**拒绝提交**
- 推送前再跑一次全量扫描：`python3 /root/.hermes/scripts/privacy_scan.py --all`
- Git 提交身份用 `用户名@users.noreply.github.com`，别用真实邮箱（否则会公开）

## 常用的"查看状态"命令

```bash
git diff --cached            # 这次将要提交的内容
git show --stat HEAD         # 最近一次改了哪些文件
git reset HEAD 文件           # 取消暂存（不删改动）
git reset --hard HEAD~1      # 回退一次提交（会丢改动，慎用）
```

## 踩的坑

1. **git 不跟踪空目录** —— 想保留目录得放个文件（如 `.gitkeep`）。
2. **`git reset --hard` 会丢未提交改动**，执行前先 `git status` 确认。
3. **仓库里中文文件名没问题**，但脚本读文件名要用 `git ls-files -z`（否则中文路径被转义成 `\346...`，读不到文件）。
4. 提交里带的**作者邮箱**也是公开信息 —— 我第一次提交就漏了本机名，后来重写历史才干净。
