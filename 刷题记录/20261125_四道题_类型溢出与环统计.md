# 四道题：二进制转数、斐波那契、旋转环计数、左移补零

## 一、32 个 0/1 转十进制

按权展开，A0 是最低位。看似简单，三个地方会翻车。

b 一路乘 2，到第 31 位要等于 2 的 31 次方，超过 int 上限，直接溢出成负数。x 最大是 2 的 32 次方减一，约 42.9 亿，也超 int。

printf 用 %d 打 long long 只输出低 32 位，要写 %lld。

正确做法是 x、b 都用 long long，或者干脆用 unsigned long long 加移位，注意 1ULL 不能写成 1。

## 二、斐波那契：循环下标写错与 RE

题目第 n 次是前两次之和，f(1)=f(2)=1，标准斐波那契。n 到 50 时 f(50)=12586269025，必须 long long。

第一版错在循环里写成 f[n]=f[n-1]+f[n-2]，变量 i 没用上，n-1 和 n-2 还是未初始化的垃圾值。n 不超过 4 时因为硬写了 f[3] 恰好蒙对，往上就全错。

改对之后交上去是 RE。RE 是运行时错误，最常见原因是数组越界。题面写 n≤50，但提示是“404 NOT FOUND”，这类玩笑通常意味着真实数据更大，f[i] 写出去了。

最稳的做法是不用数组，两个变量滚动，O(1) 空间，怎么都不会越界。

## 三、旋转环计数（最难的一题）

问 [L,R] 里有多少对 a<b，其中 b 是 a 的循环移位（把后面一段搬到前面）。

钥匙是把旋转看成环：45678 的四个旋转和它自己一共五个，任意两个都能配对，贡献 C(5,2)=10 对。所以答案就是每个环里落在范围内的元素数 k 的组合数之和。

实现：开一个按值下标的 visited 数组，从 L 扫到 R，遇到没访问过的数就把它的全部旋转算出来，落在范围内的标记并计数，累加 k(k-1)/2。

两处错误值得记：环内计数器的初值是 1 不是 0，因为自己在进循环前就被标记了，从 0 开始会让每个环少算一档，两元素环直接变成 0 对；visited 数组要开到 10 的 7 次方加 5，按 R 的上限开。

另一版是不用 visited 数组，对每个数只数比它大的旋转，每对刚好被小数数一次，代码短、内存小，但周期数（1212 这种）要去重，不然会重复计。

## 四、左移补零

把序列前 k 个删掉，末尾补 k 个 0。不用真移动元素，输出时先打 k+1 到 n，再打 k 个 0 就行。

数据是多组的，外面要套 while(cin>>n>>k) 读到文件结束。数组放全局，放 main 里会爆栈。

## 五、这四道题的共同教训

类型：2 的 31 次方、2 的 32 次方、f(50) 都超 int。看到大数先想数据类型。

数组：一律按上限的 1.1 到 1.2 倍开，或者干脆不用数组。卡着上限开，越界了不会报错，可能悄悄改掉别的变量，也可能踩返回地址直接崩，同一份代码换个编译器结果都不一样。

输入：交互式测试时 while(cin>>x) 不会自己停，要按 Ctrl+Z。长度固定就写 for 循环。

计数：计数器初值错一位，误差随规模成比例放大，答案差一倍时先怀疑起点。
